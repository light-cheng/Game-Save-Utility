# Game Save Utility v0.1.3

## 发布类型

性能优化 / 架构去重 / 自动化发布 / 合规与本地化增强

本版本重点改进后台变更检测性能（消除 UI 主线程 SHA-256 全盘哈希开销）、架构模块去重、添加开源许可证、建立自动化 GitHub Actions 发布流程，并补全错误提示中英文对称映射。

## 相较上个版本的主要变化

- **性能优化（指纹优先检测）**：引入两级变更检查机制（轻量指纹 `QuickDirectoryFingerprint` + 完整哈希），在后台定时检查存档变更时，优先比对文件总数、总大小与最新修改时间（mtime）。只有指纹变动时才计算全盘 SHA-256 哈希，彻底消除后台检测对主线程造成的卡顿与高 I/O 消耗。
- **开源合规与元数据完善**：正式添加 MIT 开源许可证（`LICENSE`），在 `Cargo.toml` 中补齐 package repository、readme 和 license 规范字段。
- **CI/CD 自动化发布**：新增 GitHub Actions 自动化工作流（`.github/workflows/release.yml`），在推送 `v*` 标签时自动运行代码格式检查、单元测试、Clippy 静态分析，并在 Windows 环境下构建打包并发布 Release。
- **架构去重（单一事实来源）**：重构游戏预设库与 Steam 路径识别逻辑，消除 `presets.rs` 与 `steam.rs` 之间的规则冗余，确立 `presets.rs` 作为已知游戏存档规则的唯一数据源。
- **错误提示本地化加固**：修复中英文错误提示的泄漏与回退不对称问题，完善双语错误上下文与错误文本映射，杜绝中文界面残留技术性英文错误信息。
- **发布规范与仓库整洁度**：标准化发布资产命名规范（`GameSaveUtility-v{version}-windows-x64.*`），将项目根目录下的界面截图统一收纳至 `docs/images/` 目录。
- **PE 元数据动态同步**：Windows 构建脚本 `build.rs` 改为动态读取 `Cargo.toml` 中的版本号，消除多处硬编码。

## 修复的问题

- 修复后台自动备份/变更检测定时器在 UI 线程全量计算 SHA-256 导致的卡顿问题。
- 修复 `presets.rs` 和 `steam.rs` 双重维护游戏预设规则的不一致隐患。
- 修复部分异常场景下中文错误提示残留英文底层错误的问题。
- 修复缺少正式许可证文件与标准 Cargo 清单元数据的问题。
- 修复发布流程依赖纯手动打包、缺乏自动化 CI 验证的问题。

## 兼容性说明

- 早期版本创建的增量备份（CAS 对象库）、ZIP 压缩备份和完整复制备份完全兼容，正常识别与恢复。
- 配置文件 `%LOCALAPPDATA%\GameSaveUtility\config.json` 保持无缝兼容。
- 本项目继续定位为纯净、独立的 Windows 桌面工具，无任何外部运行时依赖。

## 升级建议

推荐所有用户升级。对于配置了自动备份、存档变更提醒或拥有大容量存档目录的游戏，升级后能大幅减少 CPU 与磁盘 I/O 消耗，交互更加流畅。
